# CSLR — Криптографический мессенджер с 2FA и ЭЦП

Консольная утилита на языке **C**, реализующая защищённый обмен сообщениями с двухфакторной аутентификацией (2FA), гибридным набором криптографических примитивов (российские стандарты ГОСТ и сверхдлинный многопростой RSA) и проверкой целостности/авторства через электронную цифровую подпись (ЭЦП).

---

## Реализованные криптографические алгоритмы

1. **«Стрибог-512» (ГОСТ Р 34.11-2012)** — криптографическая хэш-функция с длиной выхода 512 бит (64 байта):
   * Оптимизированная табличная реализация преобразований `LPS` (подстановка `S`, перестановка `P` и линейное преобразование `L` объединены в предвычисленную таблицу).
   * Используется для:
     * хэширования паролей пользователей в БД;
     * формирования 256-битного ключа защиты личного ключевого контейнера (`pass_hash[0..31]`);
     * вычисления дайджеста сообщений перед формированием/проверкой ЭЦП.

2. **«Кузнечик» (ГОСТ Р 34.12-2015)** — симметричный блочный шифр с размером блока 128 бит (16 байт) и длиной ключа 256 бит (32 байта):
   * Используется для шифрования сообщений в режиме ECB и защиты личного ключевого контейнера пользователя (`*.key`).

3. **Multi-Prime RSA-32768 (4096 байт)** — асимметричный криптоалгоритм с длиной модуля **32 768 бит (4096 байт)**:
   * Реализован на базе библиотеки длинной арифметики **GNU MP (GMP)** с многопоточной генерацией простых чисел (`pthread`, решето + тест Ферма + тест Миллера — Рабина).
   * Каждый пользователь при регистрации получает **две независимые пары ключей RSA-32768**:
     * `enc_pub` / `enc_priv` — для асимметричного шифрования сообщений;
     * `sign_pub` / `sign_priv` — для формирования и проверки ЭЦП (схема *Hash-then-Sign* на базе Стрибог-512).

## Архитектура безопасности и 2FA

Система разделяет публичное хранилище и личные секреты пользователя:

* **Публичная база данных (`assets/cslr_db.json`)** — хранит логины, 512-битные хэши паролей, открытые ключи пользователей (`enc_pub`, `sign_pub`), симметричный ключ чата и массивы входящих сообщений (`inbox`).
* **Личный ключевой контейнер (`assets/<login>.key`)** — бинарный файл (второй фактор аутентификации), содержащий закрытые ключи `enc_priv` и `sign_priv` вместе с контрольной меткой `CSLR_OK!`. Контейнер зашифрован алгоритмом **«Кузнечик»** на ключе, вычисляемом «на лету» из первых 256 бит хэша пароля пользователя.

Для входа и работы с сообщениями проверяются **два фактора**:
1. **Фактор знания:* совпадение `Streebog-512(password)` с записью в БД.
2. **Фактор владения:** наличие файла `*.key` и его успешная расшифровка паролем.

## Структура проекта

```text
cslr/
├── assets/                 # База данных cslr_db.json и зашифрованные контейнеры *.key
├── src/
│   ├── algo/
│   │   ├── kuznyechik/     # ГОСТ Р 34.12-2015 «Кузнечик» + юнит-тесты (GoogleTest)
│   │   ├── rsa/            # Multi-Prime RSA-32768 (4096 байт) + юнит-тесты
│   │   └── stribog/        # ГОСТ Р 34.11-2012 «Стрибог-512» + юнит-тесты
│   ├── storage.h           # Интерфейс БД (cJSON) и криптоконтейнеров 2FA
│   ├── storage.c           # Реализация хранилища, шифрования контейнеров и проверки ЭЦП
│   └── main.c              # Точка входа и парсер аргументов командной строки
└── CMakeLists.txt          # Конфигурация сборки CMake
```

## Зависимости и сборка

### Требования (Ubuntu / Debian)
```bash
sudo apt update
sudo apt install build-essential cmake pkg-config libgmp-dev libcjson-dev
```
*(Для запуска модульных тестов алгоритмов также требуется `libgtest-dev`).*

### Сборка основной утилиты
```bash
cmake -B build
cmake --build build -j
```
После сборки исполняемый файл появится по пути `./build/cslr`.

## Примеры использования

### 1. Регистрация пользователей (генерация ключей и 2FA-контейнера)
```bash
./build/cslr --register --login alice --password pass1
./build/cslr --register --login bob --password pass2
```
Создаёт записи в `assets/cslr_db.json` и зашифрованные файлы ключей `assets/alice.key`, `assets/bob.key`.

### 2. Отправка зашифрованных сообщений (с автоматической ЭЦП)
```bash
# Шифрование симметричным алгоритмом «Кузнечик» (ГОСТ Р 34.12-2015)
./build/cslr --login alice --password pass1 --send --to bob --kuznyechik --msg "Привет через Кузнечик!"

# Шифрование асимметричным алгоритмом RSA-32768 (4096 байт)
./build/cslr --login alice --password pass1 --send --to bob --rsa --msg "Секретное сообщение по RSA-32768!"
```

### 3. Получение, расшифровка сообщений и проверка ЭЦП
```bash
./build/cslr --login bob --password pass2 --get --msg
```
Утилита проверит оба фактора аутентификации Боба, выведет шифртекст каждого сообщения в HEX-формате, расшифрует текст и проверит цифровую подпись отправителя по его открытому ключу из БД.
